# NeoContent 1.7.0

V1.7 adds the website-understanding layer that runs before topic selection.

## What it learns

- Published posts, pages and public custom post types.
- Public categories, tags, menus, SEO titles and descriptions.
- Featured-media alt text and captions, plus media attached to published content.
- Public URLs, titles, excerpts, dates, bylines and internal-link structure.
- Elementor editorial text through a strict allowlist without rendering shortcodes or dynamic widgets.

## Product behavior

- New customers see **Learning your website** before the first research item.
- The cloud stores a content-hash inventory and refreshes it incrementally.
- Existing titles block duplicate topics and provide internal-link candidates.
- Only representative editorial samples influence brand voice.
- Research and brief creation remain blocked until learning completes.

## Security boundary

- The inventory endpoint requires a purpose-separated, replay-protected cloud signature.
- The plugin never exports drafts, private posts, revisions, comments, users, orders, form submissions or credentials.
- Website text is treated as untrusted data and screened for prompt-injection language.
- Inventory tables have RLS enabled and no `anon` or `authenticated` access.
- WordPress performs no recurring outbound work or NeoContent cron polling.

Apply `supabase/migrations/009_site_content_learning.sql` before deploying the cloud and plugin together.
