# Registry-first external data rule

NeoContent is a consumer of `abztabz/NeoOS-Source-Registry`.

When NeoContent needs a new external public-data capability, check the shared registry first. Do not independently select a new API vendor inside NeoContent. Provider governance, lifecycle, licensing/privacy boundaries, fallback priority and shared adapters originate in the standalone registry.

NeoContent retains ownership only of content-specific interpretation: website learning, research lead curation, opportunity scoring, Luna briefing, drafting, approval and publishing.

The existing local data-gateway runtime is a temporary production compatibility copy until a versioned shared consumption mechanism is cut over and verified.
